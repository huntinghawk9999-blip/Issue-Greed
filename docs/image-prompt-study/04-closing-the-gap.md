# 04. GPT에 가깝게 만드는 방법, 보완 도구, 목적별 추천

순서는 "효과가 클 것으로 보이는 순"이에요. 직접 생성 테스트를 하지 않았으니 순서 자체는 **[판단]**이고, 각 항목의 사실 근거는 괄호 안에 적었어요.

---

## 1. 보완 도구: Venice 웹에서 되는지, 로컬에서만 되는지

| 방법 | Venice 웹 | 로컬 | 근거 |
|---|---|---|---|
| **포즈 제어 (ControlNet, 포즈 레퍼런스)** | **불가.** 공개 문서에 ControlNet이나 포즈 입력이 없어요. 참조 이미지 기능은 스타일 참조(Krea v2·Luma 계열 전용)와 편집용 다중 이미지뿐이에요 | **가능.** SDXL(Lustify v8 체크포인트)에는 OpenPose·Depth·Canny ControlNet 생태계가 넓어요. Chroma는 "일부 Flux ControlNet이 작동한다"는 보고가 있지만 어떤 모델인지 명시된 자료는 없어요 | [공식: Venice 문서] / [커뮤니티: Chroma1-HD 토론, Civitai 워크플로] |
| **구도용 이미지 → 그걸 기반으로 생성 (img2img)** | **고전적 img2img 없음.** 디노이즈 강도 조절이 없어요. 대신 지시문 기반 편집이 있어요(무검열 편집 모델 `qwen-edit-uncensored`) | **가능.** 디노이즈 0.5~0.7로 구도를 유지하면서 질감을 새로 그리는 방식이 표준이에요 | [공식] / [판단] |
| **손·발·얼굴 부분 보정** | **가능 (인페인팅).** 웹에 마스크 인페인팅 도구가 있어요(2026-07~08). 다만 마스크 인페인팅에는 프롬프트 향상이 **자동 적용**된다는 변경 기록(2026-08)이 있어서, 끌 수 있는지는 확인 안 됨이에요 | **가능.** 얼굴·손 자동 감지 후 다시 그리기(ComfyUI Impact Pack의 FaceDetailer, A1111·Forge의 ADetailer). Lustify는 제작자가 인페인팅 전용 체크포인트(APEX INPAINTING)를 따로 배포해요 | [공식: Venice 변경 기록, Civitai] |
| **업스케일** | **가능.** 2배·4배(최대 4,096²), `creativity` 0~0.02. Topaz 업스케일러도 있어요 | **가능.** 하이레스 픽스(2단계 생성), 타일 업스케일 | [공식] |
| **고해상도 보정 (하이레스 픽스)** | 확인 안 됨. 문서에 없어요 | **가능.** Lustify DMD2 버전 권장: 1.4배, 2~3스텝, 디노이즈 0.45. WAI 권장: 1.5배, 20스텝, 디노이즈 0.35~0.5 | [공식: 제작자 설명] |
| **추가 모델 (LoRA)** | **불가.** API 문서에 "사용자 LoRA 파일을 받지 않는다", 조절은 `lora_strength`뿐이라고 적혀 있어요 | **가능.** Lustify v7 제작자는 DMD2 LoRA를 "속도와 얼굴·손 문제 해결"용으로 권해요. Chroma는 Flash 델타 가중치(강도 조절해 적용)가 공식으로 있어요. Chroma1-HD 전용 피부 질감 LoRA는 확인 안 됨 | [공식] |
| **네거티브 보완 (저CFG 모델)** | 불가 | **가능.** NAG(Normalized Attention Guidance)는 저스텝·CFG 1 모델에서 네거티브를 되살리는 방법이고, ComfyUI 노드가 있어요. Lustify 제작자도 언급해요 | [공식: NAG 저장소, Civitai] |

## 2. GPT에 가깝게 만드는 방법

### 2-1. 사진 품질

**Venice 웹**

1. **모델 선택:** 피부·몸 질감이 우선이면 Lustify v8(실사 여성 특화 학습), 다양한 질감·조명이 우선이면 Chroma로 고르세요 (01-models.md §3).
2. **"사진" 매체 지정 + 미사여구 제거:** `photograph` / "This is a photograph shot on ... film"으로 시작하고, `beautiful`·`elegant`·`luxurious` 같은 단어는 재질·물체 묘사로 바꿔요 [커뮤니티: Chroma 계열 보고].
3. **CFG를 낮게:** Lustify v8은 3.5~4 [제작자 샘플]. 높은 CFG는 과포화·과선명이라는 AI 특유의 인상으로 이어져요 [판단].
4. **스타일 프리셋과 프롬프트 향상 끄기:** 프리셋 텍스트가 글자 수를 먹고, 향상 기능은 `cinematic`·`dramatic` 같은 연출어를 더하기 쉬워요 [공식 + 판단].
5. **필름 효과는 눈에 보이는 결과로:** `film grain, halation, soft highlight roll-off`처럼 써요.
6. **얼굴만 매끈해지면 인페인팅:** 얼굴만 마스크로 잡고 "natural skin texture with visible pores, same texture as the neck"로 다시 그려요.
7. **업스케일 creativity는 기본값(0.01) 이하:** 업스케일러가 디테일을 지어내면 질감이 플라스틱처럼 변할 수 있어요 [판단].

**로컬**

1. **Chroma1-HD 원본 설정:** 26~40스텝, CFG 3~4, beta 스케줄러, shift 1.0. Flash보다 디테일이 많아요(공식 워크플로 메모: shift 1.0이 "디테일이 더 좋음").
2. **양자화는 VRAM이 허락하는 최고 정밀도:** 본체 Q8/fp8, T5는 fp16 또는 Q8 (01-models.md §5).
3. **2단계 생성:** 1차를 낮은 해상도로 만들고, 1.3~1.5배로 키운 뒤 디노이즈 0.3~0.45로 다시 그려요. 피부·머리카락 디테일은 이 단계에서 가장 많이 늘어요 [판단].
4. **얼굴 디테일러:** 얼굴 영역만 높은 해상도로 다시 그리되, 프롬프트에 몸과 같은 질감 지시를 넣어 따로 놀지 않게 해요.
5. **그레인은 후처리로:** AI가 그린 그레인보다 실제 그레인 오버레이가 사진처럼 보여요. 필름 에뮬레이션 프로그램 같은 일반 사진 도구로 해요 [판단].
6. **LoRA:** Lustify를 로컬에서 쓰면 제작자 권장 DMD2 LoRA를 써 보세요. Chroma 피부 LoRA는 검증된 게 없어서 맨 뒤 순서예요.

### 2-2. 구도 재현력

**Venice 웹**

1. **구도가 핵심이면 T5·언어 모델 인코더 모델:** Chroma, 또는 노출이 없는 장면이면 Z-Image Turbo. CLIP만 쓰는 Lustify보다 관계·위치 지시를 잘 따를 구조예요 [판단: 인코더 구조].
2. **물리 충돌 제거 + 부위별 명시:** 03-conversions.md의 보정판처럼 무릎·손·발을 하나씩, 좌우는 보는 사람 기준으로 써요. 충돌이 남아 있으면 GPT보다 훨씬 쉽게 무너져요.
3. **중요한 지시를 앞쪽에:** CLIP은 77토큰 단위로 끊기니, Lustify에서는 자세와 배치를 첫 청크(약 300자) 안에 넣어요.
4. **시드 고정 반복:** 마음에 드는 구도의 시드를 찾은 뒤 질감 관련 단어만 바꿔요(Venice FAQ: 이미지 설정에 시드 입력).
5. **인페인팅으로 손발 수정:** 마스크로 해당 부위만 다시 그려요.
6. **[판단] 구도를 다른 모델에서 빌려오기:** GPT나 Z-Image로 착의 상태의 구도 이미지를 만들고, Venice 편집(`qwen-edit-uncensored`)으로 바꾸는 방식이에요. 다만 편집을 거치면 질감이 바뀔 수 있고, 편집 모델의 결과 품질은 확인 안 됨이에요.

**로컬**

1. **포즈 ControlNet:** 원하는 자세의 뼈대(OpenPose)나 깊이 맵을 입력해요. 좌우·손발 문제를 프롬프트가 아니라 이미지로 지정하니까 가장 확실해요. Lustify(SDXL)에서는 확실하고, Chroma는 호환 모델 확인이 필요해요.
2. **구도용 이미지 → img2img:** 3D 포즈 도구나 간단한 합성 이미지로 배치를 만들고, 디노이즈 0.55~0.7로 다시 그려요.
3. **2단계 조합:** 구도는 SDXL+ControlNet으로 잡고, 질감은 Chroma img2img(낮은 디노이즈)로 입히는 방법이에요 [판단].
4. **디테일러로 손발 정리.**

### 2-3. 장면 추론력

**Venice 웹·로컬 공통** (도구가 아니라 프롬프트 작성 단계의 문제라서 둘이 같아요)

1. **02-scene-expansion.md 체크리스트를 언어 모델로 돌리기 (2단계):** 확장 표 → 사람 확인 → 대상 모델 형식으로 조립. 효과도 가장 크고 통제도 가장 잘 돼요.
2. **모델별 분량 조절:** Chroma는 8~12개 문장, Lustify는 4~6개 태그. 확장이 다른 지시를 밀어내지 않게 해요.
3. **Venice 프롬프트 향상을 "아이디어 수집용"으로만:** 공식 문서의 팁 3번이 "향상된 프롬프트를 헤더(웹은 팝오버)에서 받아 두고, 향상을 끈 채 그 텍스트를 재사용하라"예요. 이걸 응용해서 향상 결과를 한 번 받아 보고, 체크리스트 규칙(인과·비추가·가시성·충돌)으로 걸러서 남은 항목만 내 프롬프트에 넣어요. 그대로 쓰면 의도가 바뀌어요.
4. **충돌은 미리 질문으로 정리:** "소나기 + 황금빛 햇살"처럼 부딪치는 조합은 생성 전에 하나로 정해요.

## 3. 목적별 추천 모델

전부 **[판단]**이에요. 근거는 학습 목적과 인코더 구조이고, 직접 비교한 결과가 아니에요.

| 목적 | Venice 웹 1순위 | Venice 웹 2순위 | 로컬 | 이유 |
|---|---|---|---|---|
| **실사 화보 (착의)** | Chroma | Lustify v8 | Chroma1-HD (+디테일러, 하이레스) | 화보는 구도·공간 표현 비중이 커서 T5 인코더가 유리해요. 피부 질감이 부족하면 Lustify v8로 같은 구도를 다시 시도해요 |
| **실사 누드** | Lustify v8 | Chroma | Lustify v8 체크포인트 + 포즈 ControlNet, 또는 Chroma1-HD | Lustify는 실사 여성 누드에 맞춰 학습됐다고 제작자가 밝혀요. 구도가 복잡하면 Chroma가 나을 수 있어요 |
| **회화풍 (유화·수채 등)** | Chroma | — | Chroma1-HD | Chroma 학습 데이터에 예술 스타일이 포함돼 있고, 자연어로 화풍·붓질·재료를 묘사할 수 있어요. Lustify는 사진 쪽으로 강하게 치우쳐 있어요 |
| **애니·일러스트** | Anime (WAI) | Chroma | WAI 로컬 체크포인트 | WAI는 애니 전용이에요. 나이 표현은 `mature female` 앞쪽 배치로 관리해요 |
| **조각풍 (대리석상 등)** | Chroma | — | Chroma1-HD | 재질(대리석, 청동), 전시 조명, 받침대를 문장으로 묘사해야 해서 자연어 모델이 맞아요 |
| **빠른 구도 시안** | Z-Image Turbo (노출 없는 장면) / Chroma | — | Chroma Flash | 8~10스텝 |
| **피해야 할 선택** | 자동(Auto) | — | — | 라우팅 기준이 공개돼 있지 않아서 같은 프롬프트로 다른 모델이 걸릴 수 있어요. 비교·반복 작업에는 맞지 않아요 |

### 다음 단계 제안

1. 03-conversions.md의 Lustify v8·Chroma A/B 4개를 **같은 시드**로 생성해서, 보정판에서 무릎·손·노트북 배치가 실제로 개선되는지 확인해요.
2. Venice 웹에 네거티브 입력란과 CFG 슬라이더가 있는지 화면에서 확인해 주세요. 01-models.md의 "확인 안 됨" 항목 중 가장 영향이 큰 두 가지예요.
3. 로컬 환경 정보(UI, GPU·VRAM, 받은 파일)를 알려 주시면 양자화 선택, ControlNet 호환 모델, 디테일러 워크플로를 확정할게요.
